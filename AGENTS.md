# Раскладка полей каталога Д1–Д20 — обязательна для ВСЕХ адаптеров (v1.6)

Решение пользователя от 2026-09-23. **Стандарт при написании/правке ЛЮБОГО скрипта-адаптера
источника** (`prlib_card`, `neb_notion`, `rgada_notion`, `rgia_notion`, `permkrai_notion`,
`export_gpib_notion`, `rnb_*`, `rsl_*` и все будущие онлайн-библиотеки/архивы).

**Полная таблица раскладки** — `docs/current/ЗАДАНИЕ_адаптеры_новые-правила-полей_v1.6_2026-09-23.md`;
**канон описаний полей** — `Каталогизация/igis-sources-catalog/catalog_guidelines_ru.md` v1.6.
Адаптеры раскладывают данные единообразно по этой таблице, не «как удобно источнику».

Сквозной принцип: **есть в карточке → в поле; пусто только когда данных реально нет**; спорное →
кандидат + review-флаг, не догадка. Инварианты, которые скрипты чаще всего нарушают:
- держатель оригинала (РГБ/ЦВМБ/ГПИБ…) → **«Архив хранения»** (relation на существующую запись
  справочника), **НЕ «Место хранения»**; агрегатор (ПрБ/НЭБ) не поле — виден по URL карточки;
- архивный шифр («РГИА.Ф.1290.Оп.4.Д.68») → распарсить в **Фонд/Опись/Единица хранения**;
- источник эл. копии → **«Организация оцифровки»**;
- **весь текст карточки → «Описание»**; поле **«Библиографическое описание» упразднено** (слито);
- год: точный → нижняя; диапазон → +верхняя; библиотека без даты создания → год издания в верхнюю
  с пометкой «(авто)»; **«Год источника»/«Шифр записи» — формулы Notion, маппер их НЕ пишет**;
- издание → 5 полей «Связанное издание: …»; **«…библ. описание» упразднено**; URL только настоящий;
- автор **карты** ≠ ответственность издания (последняя → «Связанное издание: автор»); нет автора карты → пусто;
- язык → **авто «Русский»**, если в карточке явно не указан другой;
- территория → только подтверждённая единица справочника (морфо-совпадение), иначе пусто + флаг «регион неясен»;
- серия → детектор A (маркеры Лист/Том/Вып/№/Ч.) + детектор B (кластер прогона ≥3); новую серию авто НЕ создавать;
- **«Путь / URL к файлу» ≠ URL карточки** (URL карточки только в «Ссылки на онлайн-архив», иначе ложная «цифровая копия»);
- Блок IV (год скан./DPI/качество/цветность/формат/размер/лицензия) — только если есть в карточке/файле;
- статусные поля (геопривязка/векторизация/OCR/GCP) — дефолты, при обновлении **не сбрасывать** (защищённый список импортёра);
- «Примечания» — наши аналитические пометки (review-флаги, основания типизации), **НЕ текст карточки**;
- служебные: Автор внесения=**Агент**, Статус приёмки=**кандидат** (`ready_for_import=false`).

Границы: заливка в Notion — **только мост** `notion_upload_candidates.py` (REST + дедуп по URL), **не MCP**;
логику фильтра `run_review.py::decide`/`triggers.py` **не трогать**; гейт готовности адаптера —
`ruff` → прогон на реальном наборе → выборочная сверка раскладки. Расхождение правил ↔ карточек —
в сессию разбора полей (правки канона v1.6), не «решать на месте».

# Извлечение недостающих характеристик из изображений

Решение пользователя от 2026-09-12. Область: все онлайн-библиотеки проекта
(включая ГПИБ, Президентскую библиотеку, РНБ, РГБ, НЭБ) и ЭБИД.

- После чтения карточки проверять недостающие поля: масштаб основной карты,
  автор/составитель, сведения об издании (название, год, место, издатель),
  а также другие согласованные характеристики. Проверять доступность скана.
- При наличии разрешённого изображения/PDF предусматривать автоматическое
  распознавание, предпочтительно по исходному разрешению. Различать полную
  цифровую копию, галерею отдельных страниц, обложку и метаданные.
- Автоматически распознанное значение — candidate, не подтверждённый факт.
  Сохранять исходный текст, URL/локальный файл, SHA-256, страницу, координаты
  фрагмента, инструмент/версию и оценку уверенности. Не подменять confidence
  вероятностью правильного исторического утверждения.
- Заполненные поля карточки не перезаписывать результатом OCR. Противоречия,
  неоднозначные роли и неуверенное чтение предъявлять пользователю. Принятые
  значения переносить в рабочие поля после проверки; Notion — отдельный этап.
- Исключать врезки и дополнительные планы: не создавать из них источники и
  не переносить их масштаб/авторов/характеристики на основную карту. Если
  граница не установлена, распознавание остаётся на ручной проверке.
- Не вычислять знаменатель масштаба по экранному размеру или масштабу врезки.
  Линейный масштаб без надёжной физической привязки сохранять дословно.
- Различать автора карты, автора издания, издателя, гравёра и типографию;
  год издания не смешивать с изображаемым временем, съёмкой и оцифровкой.
- Отсутствие скана/надписи фиксировать, не восполнять догадкой. Не обходить
  запреты доступа; не загружать модели/зависимости или передавать изображения
  внешнему сервису без требуемого разрешения.
- Правило общее, но подключение проверять отдельно для каждого источника:
  просмотрщики, ссылки и разметка различаются. Не объявлять весь механизм
  реализованным по одному ручному чтению или одному OCR-тесту.

## Обязательная проверка издания и дат

Решение пользователя от 2026-09-12 для всех онлайн-библиотек и ЭБИД:
- Связанное издание проверять обязательно: название, URL, год, место,
  издатель и полное библиографическое описание. При наличии ссылки изучать
  страницу издания. Указатель документов не считать библиографической карточкой.
- В ЭБИД исходный сборник брать из «Источник документа»; сведения о более
  ранней публикации сохранять отдельно. Счётчики сайта не являются частью записи.
- Неизвестное издание отмечать как неустановленное и отправлять на проверку,
  не выдумывать URL. Для самостоятельной карты описывать собственное издание.
- Дату карты связывать с её названием, не с колонтитулами и заголовками книги.
  «На ... год» — изображаемое время, не доказанный год создания.
- Для ЭБИД 87164 пользователь подтвердил масштаб 1:12 000 000 и исключение
  заголовка раздела «1917 год». 1914 — изображаемое время; 1978 — публикация
  в атласе (с. 20); 2001 — исходный сборник (скан с. 41).
  Подтверждение ручное, не результат автоматического OCR.

Текущий этап — последовательная совместная проверка источников и скриптов,
не общий прогон. В ГПИБ ранее выполнено ручное чтение, не автоматический OCR.

## Госкаталог: обязательное дополнение по изображению

Решение пользователя от 2026-09-12. Для карт Госкаталога музейного фонда
после извлечения всех полей карточки обязательно проверять недостающую
информацию по приложенному изображению и предусматривать её распознавание.
Кандидаты: масштаб основной карты, автор/составитель, издатель/типография,
место и год издания, сведения о съёмке, исправлениях и связанные издания.

- Отсутствие кнопки скачивания не означает отсутствие изображения. Проверять
  адреса img/src, ng-src, data-zoom-image в доступном HTML и сохранённые
  браузером файлы рядом с HTML. В «Прямая ссылка на файл изображения»
  переносить установленный исходный URL, не локальный относительный путь.
  Сетевую доступность URL отмечать отдельно от его наличия в HTML.
- Лупа может увеличивать тот же файл без дополнительных деталей. Для
  проверенного образца 64725053 найден JPEG 600x800, и лупа использует
  тот же адрес; не распространять это наблюдение на все карточки без проверки.
- Сначала использовать все сведения карточки, включая свободный текст
  внизу: пустое поле «Материал, техника» не исключает описания материала там.
- Применять общие правила OCR выше: не перезаписывать заполненные поля,
  исключать врезки, сохранять evidence и статус candidate, показывать
  дополнения и противоречия пользователю. Неуверенное чтение/низкое разрешение
  — причина оставить поле пустым и направить запись на ручную проверку.
  Обязателен этап проверки, а не выдуманное заполнение каждого поля.
- Различать дату создания и изображаемое время. Для карты Козельского уезда
  (URL id=64808369, номер Госкаталога 64520909) пользователь подтвердил
  1926 год в легенде границ волостей. Это ручное подтверждение изображаемого
  времени, не OCR и не установленный год создания; сохранить в примечаниях
  вместе с датой 25.10.1917 из заголовка карточки. Период создания «XX век»
  не заменять этими датами без дополнительных оснований.
- Это утверждённое требование к обработке Госкаталога. Автоматическое
  распознавание и его интеграция в сборщик пока не реализованы и не проверены;
  запись правила не считать завершением реализации. Notion не изменять
  без отдельного разрешённого этапа импорта.
