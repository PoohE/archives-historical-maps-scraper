# Контур ручной проверки и самообучения

Введён 2026-10-04 по требованию пользователя: два механизма ручной проверки сводятся в один
контур, и в нём прописывается самообучение — система должна на основе принятых решений
принимать такие решения всё более самостоятельно.

**Область действия — только проект «Поиск онлайн архив» (онлайн-архивы).** В работу со статьями,
АИК и прочие проекты механизм не переносится.

---

## 1. Две стадии одного контура (а не два механизма)

| | Стадия A — **до импорта** | Стадия B — **в каталоге** |
|---|---|---|
| Где | лист проверки в наборе сборщика | поле «Статус приёмки» в Notion-каталоге |
| Кто ведёт | сессия сбора (эта) | сессия каталога (claude-51) |
| Что решается | брать ли спорную запись в каталог вообще | что делать с записью, уже попавшей в каталог: ошибка, переквалификация, дубль, неполнота |
| Инструмент | `output/manual_review_<дата>/РУЧНАЯ_ПРОВЕРКА.html` + `decisions.csv` | свойство Notion (select) + «Причина сомнительности» + «Примечания» |
| Результат «нет» | запись не вносится, уходит в `scope_drops.jsonl` с `scope_drop_reason=human_rejected` | запись остаётся в базе со «Статус приёмки = отклонено» (не удаляется) |

Разделение смысловое: **стадия A решает «входит ли», стадия B — «что с тем, что уже вошло»**.
Поэтому они не дублируют друг друга, и отклонение на стадии A не создаёт записи в Notion.

## 2. Единая схема решения

Обе стадии приводятся к одному журналу `decisions.csv` со столбцами:

`url` (ключ сопоставления) · `decision` · `stage` · `source` · `territory` · `title` ·
`question` · `duplicate` · `from_image` · `human_note`

Отображение статусов Notion в `decision`:

| «Статус приёмки» (select) | `decision` | `stage` |
|---|---|---|
| принято | `yes` | `post-import` |
| отклонено | `no` | `post-import` |
| кандидат | `skip` (решение отложено) | `post-import` |

Лист стадии A даёт `yes` / `no` / `skip` напрямую, `stage = pre-import`.

**Ключ сопоставления — URL** (или его хвост-идентификатор): для НЭБ это `rusneb.ru/catalog/000199_000009_…`,
для Перми — URL страницы, для архивов — `rgada.info`/`online.archives.ru` плюс поля Фонд/Опись/Ед. хр.
Номер строки в листе проверки ключом быть не может: наборы пересобираются и нумерация смещается.

Причины со стороны Notion: «Причина сомнительности» (multi_select: сомнительный тип; нет маркера
карты; регион неясен; год не указан) ложится в `question`, «Примечания» — в `human_note`.

⚠️ Поля «кто и когда принял решение» в схеме Notion нет («Автор внесения» — это кто внёс, а не кто
решил). Для журнала это терпимо, но если понадобится прослеживаемость решений — заводить отдельное
поле; решение пользователя.

## 3. Самообучение

Журнал и движок — одни на обе стадии:

| Файл | Назначение |
|---|---|
| `УРОКИ_ОТБОРА.md` | **читать ПЕРЕД** любым отбором, написанием гейта или брифа сборщику |
| `УРОКИ_ОТБОРА.jsonl` | журнал: одна строка — один частный урок (`kind: case`) или принцип (`kind: principle`) |
| `scripts_review/catalog_review_lessons.py` | движок |
| `scripts_review/.review_snapshot.json` | какие решения уже разобраны (ключ — url) |

Команды:

```
python scripts_review/catalog_review_lessons.py --show                  # уроки и принципы
python scripts_review/catalog_review_lessons.py --diff                  # что ещё не разобрано
python scripts_review/catalog_review_lessons.py --learn --note "…"      # занести решения
python scripts_review/catalog_review_lessons.py --principle "…" --from "…"   # вывести правило
python scripts_review/catalog_review_lessons.py --supersede ID --note "…"    # прежний урок устарел
```

**Порядок (обязательный):**

1. **Перед** отбором, правкой гейта или написанием брифа сборщику — прочитать `УРОКИ_ОТБОРА.md`.
   Правило, противоречащее уроку, не пишется, пока расхождение не вынесено пользователю.
2. **После** каждой порции решений человека (на любой из стадий) — `--learn`, затем осмыслить:
   если несколько случаев складываются в правило, записать его `--principle` со ссылкой на случаи.
3. Урок, противоречащий прежнему, **не затирает** его: прежний помечается `--supersede`,
   расхождение выносится пользователю — какой верен.
4. Принцип, подтверждённый практикой и устоявшийся, переносится в
   `ПРАВИЛА_ОТБОРА_источников.md` как параграф правил; в журнале он остаётся с пометкой.
5. Стадия B отдаёт свои решения тем же `decisions.csv` (экспорт из Notion по изменившемуся
   статусу) — сессия каталога подтвердила, что сможет его отдавать.

**Как это делает систему самостоятельнее.** Принципы из журнала идут в три места:
(а) в гейт сборщика — как правила отсева и флагов; (б) в брифы Codex — как требования к пакету;
(в) в формулировку вопроса человеку — чтобы спрашивать только то, что действительно спорно.
Доля записей, требующих ручного решения, должна падать от прогона к прогону; это и есть мера
обученности.
