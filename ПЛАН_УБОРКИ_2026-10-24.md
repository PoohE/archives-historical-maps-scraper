### Целевая структура (этап B5)

```
Поиск онлайн архив/
├── README.md              карта: что где, как запустить, как добавить архив
├── ЖУРНАЛ.md              единственный файл состояния
├── src/                   ← на GitHub
│   ├── core/              scope_rules, false_carto, общий HTTP-слой
│   ├── sources/<код>/     по папке на архив: sweep.py, build_package.py, README
│   └── review/            аудит, кросс-дубли, сборка пакетов
├── config/                ← на GitHub: губернии, уезды, границы лет, словари ловушек
├── docs/                  ← на GitHub: регламенты, правила отбора
├── tests/                 ← на GitHub
├── data/                  ← НЕ в git
│   ├── raw/<код>/         сырая выгрузка, только последняя
│   ├── packages/<код>/    финальный пакет
│   └── reference/         эталоны и журналы решений
└── _archive/              заморозка, затем один .7z
```

**Что это даёт:** для нового архива копируется `src/sources/_шаблон/`, пишется обход и
правила отбора — гейт, территории и сборка пакета приезжают из `core/` готовыми. Сейчас
каждый новый архив начинался с копирования чужого скрипта целиком.

## Правила на время работ

1. **Ничего не удалять безвозвратно** — всё в `_archive/`, затем один `.7z`. Сырые
   прогоны воспроизводимы, журналы решений с мотивировкой — нет.
2. **Яндекс.Диск**: перенос и удаление гигабайтов вызовет долгую синхронизацию.
   На время работ синхронизацию на второй машине ставить на паузу.
3. **Две сессии в одной папке**: пока claude-45 пишет в `output/`, мы туда не пишем вовсе.
