# Поиск исторических карт в онлайн-архивах

Воспроизводимый набор read-only-скриптов, который ищет исторические карты, планы, атласы и
чертежи в открытых каталогах российских архивов и библиотек, а затем **отделяет пригодные
находки от шума** по заданным правилам. Проект в исследовательской разработке.

Задача, ради которой он написан: собрать источники для исторических геоинформационных систем
(ИГИС) по четырём губерниям — Калужской, Пермской, Смоленской и Ярославской, включая уездные
запросы. Каталог, в который попадают прошедшие отбор записи, описан отдельно:
[igis-sources-catalog](https://github.com/PoohE/igis-sources-catalog).

## Кому это может пригодиться

- историкам и географам, которым нужен воспроизводимый обход архивных каталогов, а не
  ручной перебор поисковых форм;
- тем, кто строит похожий сборщик: здесь 31 адаптер к разным системам (от современных API
  до каталогов девяностых годов) и готовые решения их особенностей;
- тем, кому важен провенанс: каждая находка хранит URL, дату получения, локатор и статус
  доступа, а спорное помечается для ручной проверки, а не досочиняется.

## Как устроено: два конвейера

Это главное, что стоит понять до чтения кода. Конвейера два, они независимы.

**1. Поиск** — ходит в сеть, собирает кандидатов.

```
scripts/run_search.py            оркестратор: источники × территории × ключевые слова
scripts/modules/                 общий движок — то, что переиспользуется всеми источниками
scripts/modules/scrapers/        карточки и парсеры конкретных систем
scripts/check_source.py          smoke-проверка одного адаптера
```

**2. Ревью-фильтрация** — офлайн, без сети, решает, что из собранного годится.

```
scripts/run_review.py            фильтр по критериям → схлопывание дублей → диф с уже внесённым
scripts_review/false_carto.py    ловушки «ложной картографии» (чертёж родословного дерева,
                                 литературная карта, картотека — слова есть, карты нет)
scripts_review/scope_rules.py    правила территориального и хронологического охвата
scripts_review/*.py             аудиты прогонов, сборка пакетов на ручную приёмку
```

Результат ревью — три корзины: оставить автоматически, отдать человеку, отсеять с указанием
причины. Отсев сохраняется: он воспроизводим и используется при разборе ошибок правил.

**Чем `scripts/modules/` отличается от `scripts_<архив>/`.** `modules` — общий движок
(транспорт, фильтры, нормализация, экспорт). Каталоги `scripts_rgia`, `scripts_gaso`,
`scripts_gayo`, `scripts_rgada`, `scripts_rgvia`, `scripts_rosarchive` и ещё два десятка —
**прогоны по конкретным архивам**: разовые скрипты, снимки состояния, доборы. Их много,
потому что каждый архив устроен по-своему; общий код туда не уезжает.

## Быстрый старт

Нужен Python 3.12 или новее.

```bash
python -m pip install -r requirements.txt

# что будет искаться — без сети и без записи результатов
python -B scripts/run_search.py --dry-run --source all

# реальный сбор в output/, без записи в Notion
python -B scripts/run_search.py --source all --no-notion --run-dir local_run

# разбор собранного: три корзины
python -B scripts/run_review.py output/local_run

# проверка одного адаптера
python -B scripts/check_source.py neb
```

Тесты парсеров (часть пропускается без HTML-снимков — это ограничение набора данных, а не сбой):

```bash
python -B -m unittest discover -s tests -t . -v
```

## Что нужно из окружения

- **Ничего обязательного для поиска и ревью**: оба конвейера работают без ключей.
- `NOTION_TOKEN` — только для локальных maintenance-скриптов, которые пишут в каталог Notion;
  основной сборщик запускается с `--no-notion`. Образец переменных — `.env.example`,
  реальные значения в репозиторий не попадают.
- Браузерный адаптер НЭБ требует Chromium Playwright, установленного локально. В CI это
  намеренно не делается.

## Границы — что проект сознательно не делает

- не обходит CAPTCHA, авторизацию, геоблокировки, антибот-защиту и TLS-ограничения;
  работает только с публично доступным;
- не скачивает сами изображения и не распространяет их: собираются описания и ссылки;
- не заполняет неизвестное догадкой — неполное поле уходит в ревью с пометкой;
- результаты прогонов, снимки страниц и локальные выгрузки **не часть публичного кода**
  и исключены через `.gitignore`;
- GitHub Actions (`.github/workflows/search.yml`) ставит зависимости и гоняет тесты;
  сетевого сбора в CI нет, токен не используется, результаты обратно не коммитятся.

## Провенанс

Каждый производный результат хранит URL, дату получения, локатор, статус доступа и связь с
исходным запросом. Записи остаются кандидатами до ручной приёмки: ни один адаптер не
переводит находку в каталог автоматически. Правила отбора и регламенты приёмки лежат рядом —
`ПРАВИЛА_ОТБОРА_источников.md`, `РЕГЛАМЕНТ_приёмки_пакета_сборщика.md`,
`РЕГЛАМЕНТ_закрытия_архива.md`, `ЧЕКЛИСТ_ПРЕДЗАЛИВКИ_полей.md`; навигатор по источникам —
`docs/НАВИГАТОР_источников_2026-10-24.md`, краткое описание проекта — `docs/project-brief.md`.
