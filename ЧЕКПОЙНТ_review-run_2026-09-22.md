## ГРАБЛИ (не повторять)
- **Прямой записи в Notion из ветки 2 НЕТ (канон п.5).** Только мост `notion_upload_candidates.py`.
  Исключение — справочники («Архивы») и DDL схемы: их правит главная сессия (MCP допустим).
- **SQL-реплика Notion MCP ОТСТАЁТ** от свежих правок на минуты: проверку результатов заливки
  делать REST-ом по конкретным страницам, не SQL-ом (ловушка 2026-09-23: SQL показывал старое
  состояние при фактически обновлённых страницах).
- **Мост в --update пишет только НЕПУСТЫЕ значения** — старое неверное значение пустым не
  затирается (поэтому чистка поля 11 понадобилась отдельным скриптом). Защищённый список при
  обновлении: Автор внесения, Статус приёмки, Дата внесения, статусы нашей работы.
- **Notion MCP не умеет удалять/архивировать** → REST `archived=true` (`notion_archive_pages.py`).
- **Формулы недоступны в SQL** (`notAvailableInQuerySql`): «Год источника»/«Шифр записи» читать
  REST-ом или rows-mode.
- **Фильтр** (`run_review.py::decide` + `triggers.py`): «Сибирь» НЕ отсеивать (Пермь=Сибирь);
  травелоги/летописи берём; перепись≠переписка; Ростов+Дон → чужой; in_scope без «карта» → review.
  После правки — обязательно `tests/test_run_review_filter.py`.
- **Codex работает в этом же рабочем дереве** (координация `CODEX_COORD_adapters_v16_20260923.md`,
  ревью `CODEX_REVIEW_adapters_v16_v3_20260923.md`): перед правкой модулей смотреть `git status`,
  его незакоммиченные файлы не трогать. Мой контур: мост, maintenance, схема, канон.
