# Бриф Codex: сборщик сканов описей ГАСО (portal.gaso-smolensk.ru)

Дата: 08.10.2026. Ставит: claude-4a (сессия сбора). Источник: Государственный архив
Смоленской области. Согласовано пользователем 08.10.

## 1. Зачем это нужно

Смоленская губерния — самая бедная по подробным картам из четырёх губерний проекта
(в РГВИА по ней 148 дел, подробных планов уровня дач и селений почти нет). ГАСО закрывает
этот пробел: по путеводителю архива только в разделе «Межевание и землеустройство» —
**23 фонда, 6 787 ед. хр.**, включая **ф. 814 «Смоленская межевая контора» (3 110 ед. хр.,
1770–1916)** с планами дач генерального и специального межевания.

Проблема в том, что **взять эти описи сейчас нечем** — отсюда и задача.

## 2. Что уже установлено (не перепроверять, это измерено)

**На портале НЕТ списка дел.** Вкладка «Единицы хранения» у описи пуста: «Данные не найдены,
0-0 из 0». Архив не загрузил дела в базу. Проверено на ф. 259 оп. 1 (id=155) по скриншоту
из браузера пользователя.

**Есть сканы описей.** Вкладка «Скан-образы описи» содержит PDF. У ф. 259 оп. 1 это файл
с подписью `259_1`. Такой PDF (87 страниц, 8,3 МБ, текстового слоя нет) у нас уже есть —
`input_gaso/document.pdf`; из него Claude Vision извлёк 268 дел.

**Адресация описей.** Прямой адрес: `https://portal.gaso-smolensk.ru/page/portal/opisView.jsf?id=N`,
где N — сквозной идентификатор по всему архиву (НЕ номер фонда и НЕ номер описи).
Зонд 12 точек в диапазоне 1…2500: **ответили все 12, у всех есть вкладка со сканом**.
Соседние идентификаторы принадлежат разным фондам: id 154 → ф. 228, id 155 → ф. 259,
id 156 → ф. 277. Страниц фонда и списка описей на портале нет: `fundView.jsf`, `fundList.jsf`,
`opisList.jsf`, `search.jsf` отдают 404.

**Номер фонда на странице описи не написан.** Единственный способ определить принадлежность —
**подпись файла скана вида `259_1`, то есть `<фонд>_<опись>`**. Это ключ ко всей карте.

**robots.txt у портала отсутствует** (404) — запретов на обход нет. Основной сайт архива
`gaso-smolensk.ru` отвечает отдельно, это WordPress, к порталу отношения не имеет.

**Скачать PDF обычным GET нельзя.** Превью скана — PrimeFaces `CommandLink`
(`form:j_idt223:dataPreview:0:j_idt475`), клик уходит POST-ом с одноразовым
`javax.faces.ViewState`. Я воспроизвёл postback: он возвращает **не файл, а
`partial-response` (text/xml, ~3 КБ)**, который открывает медиа-просмотрщик; сам PDF
приходит следующим шагом внутри этого диалога. Проба — `scripts_gaso/probe_scan_download.py`,
её вывод сохранён.

**Вот здесь и нужен пакет.** Нужно довести JSF-диалог до файла — это механика, которую
надо сделать один раз и устойчиво.

## 3. Что требуется сделать

### 3.1. Карта идентификаторов

Обойти диапазон `opisView.jsf?id=N` и построить таблицу:

| поле | откуда |
|---|---|
| `id` | параметр URL |
| `fund`, `opis` | из подписи файла скана `<фонд>_<опись>` |
| `opis_number` | поле «№ описи» на странице |
| `chronology` | поле «Хронология» |
| `title` | «Заголовок описи» |
| `has_scan` | есть ли вкладка «Скан-образы описи» и файл в ней |
| `units_in_base` | число в «Единицы хранения» (ожидается 0 — зафиксировать как факт) |

Границы диапазона определить самостоятельно: верхняя не установлена, id=2500 ещё отвечает.
Идти до устойчивой серии пустых ответов, границу записать в отчёт.

### 3.2. Скачивание сканов

Для фондов из списка §4 скачать PDF описей в `output/gaso_scans_<дата>/<фонд>_<опись>.pdf`.
Рядом — `manifest.json`: id, фонд, опись, имя файла, размер, **sha256**, дата скачивания,
URL страницы.

**Проверка на известном файле:** ф. 259 оп. 1 (id=155) у нас уже есть. Скачанный файл
сверить с `input_gaso/document.pdf` по sha256 и записать результат в отчёт. Если различаются —
не считать ошибкой, но зафиксировать (архив мог перезалить скан).

### 3.3. Режим работы

- **Пауза не менее 1,5 с** между запросами, одна параллельная нить. robots нет, но портал
  областного архива — нагружать его нельзя.
- **Состояние и возобновление обязательны**: обход 2 500+ страниц плюс скачивание сотен
  мегабайт не должны начинаться заново после обрыва.
- **Выход — только в локальную папку** (не в синхронизируемую): файлы состояния переписываются
  часто, и Яндекс.Диск на таких файлах делает конфликтные копии. У нас уже был `PermissionError
  [WinError 5]` на прогоне РГИА ровно по этой причине.
- Коды 403/429 подряд (3 и более) — штатная остановка с `exit 2` и внятным `stop_reason`,
  не продолжать «а вдруг отпустит».
- **Не выдавать парсерную ошибку за блокировку.** Прецедент ПрБ v8: `card_parser_error`
  при HTTP 200 и 53 835 байт ответа был помечен как `AccessBlocked` — из-за этого пакет
  сочли заблокированным. Классификация остановки должна опираться на код ответа, а не на
  фразу в теле страницы (прецедент Перми: `real_barrier:barrier_phrase` при HTTP 200).

## 5. Чего делать НЕ надо

- **Не распознавать PDF** — Vision-разбор делает сессия Claude, это не задача пакета.
- Не трогать `records.*`, каталог, Notion и чужие папки `output/`.
- Не писать в репозиторий ничего, кроме своего пакета и отчётов; `git add -A` запрещён —
  в рабочем дереве постоянно висят незакоммиченные правки (на 08.10 — 234 файла).
- Не пытаться достать список дел из базы портала: его там нет, это установленный факт,
  а не недоработка обхода.

## 6. Приёмка

Пакет принимается по регламенту `РЕГЛАМЕНТ_приёмки_пакета_сборщика.md`. Сверх него:

1. **Карта идентификаторов полна**: указан обойдённый диапазон, число ответивших страниц,
   число описей со сканом и без, граница диапазона с обоснованием.
2. **Манифест сходится с файлами**: число записей = числу PDF, sha256 у каждого, нет нулевых файлов.
3. **Контроль на ф. 259 оп. 1** выполнен и результат сверки с нашим файлом записан.
4. **Состав против путеводителя**: по каждому фонду из §4 сказано, найден он на портале или нет;
   ненайденные перечислены явно, а не умолчаны.
5. Классы остановок перечислены с числами (сколько 403, сколько таймаутов, сколько описей
   без скана) — одной сводной фразы недостаточно.
