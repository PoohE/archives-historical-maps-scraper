# Регламент приёмки пакета сборщика — требования к ЛЮБОМУ выходу

Версия 1.0, 2026-10-02. Адресат: Codex (и любой, кто готовит пакет).
Заменяет разовые замечания в брифах: вместо повторения одних и тех же претензий
пакет сдаётся по этому списку. Бриф описывает ЧТО собрать, регламент — КАК сдать.

Повод: дефекты повторяются из пакета в пакет (обрезанный CSV, флаг только в сводке,
незаявленные классы переходов, падение прогона от одной единицы, ложный барьер).

---

## 1. Признак живёт в записи, а не в сводке

| Обязательно | Почему |
|---|---|
| `needs_human` — **в каждой записи** (JSONL и CSV) | число в `counts` нельзя отфильтровать: каталогизатор не может отобрать 3443 записи, если признака нет в строке |
| `evidence` — **раздельно** по основаниям: предмет / территория / уровень | иначе очередь неразличима и бесполезна |
| `scope_drop_reason` — в каждой отсечённой записи | решение должно быть пересматриваемым |

Сводные счётчики в `MIGRATION_*.json` — **дополнение**, не замена.

## 2. Состав выхода проверяется по полям, а не по числу строк

- **CSV: ровно 65 колонок.** `csv_jsonl_delta: 0` сравнивает количество строк и обрезанный
  экспорт НЕ ловит. Добавить в самопроверку контроль числа и имён колонок.
- Territory, keyword и экспортный слой не теряются при переоценке.
- JSONL: 0 битых строк; `csv_rows == jsonl_rows`.

## 3. Отчёт миграции перечисляет ВСЕ классы переходов

При любой переоценке в отчёте и в докладе — **полная** матрица `from → to` с числами
и примером на класс. Называть только один класс, когда их несколько, нельзя.

*Прецедент:* в v13.8 заявлено «12 `not_cartographic` возвращены», по факту переходов 171 —
ещё **159 `city_level → keep`** не были названы. Среди них нашлись и законные исправления
(«Петроградско-Тульский поземельный банк» городом не является), и утечки:
«Карта перевальной дороги… на Кавказе» (§1.3, чужой регион),
«Строительные планы… Иконостас» (§1.1, не картография).

**Снятие отсечения — не только исправление ошибки, но и риск утечки.** Каждый класс
возвратов прогоняется против ОСТАЛЬНЫХ правил: снял `city_level` — проверь §1.1 и §1.3.

## 4. Отсечения не удаляются никогда

Отсечённая запись пишется в `scope_drops.jsonl` целиком, с причиной и исходными полями.
Удалять, а не отсекать — запрещено: решение пересматривается (так вернулись 12 записей
по расширенному §1.1).

## 5. Одна единица не останавливает прогон

Отказ на единице обработки (карточка, дело, опись, запрос) → пометить единицу,
записать причину, **перейти к следующей**. Останов всего прогона — только по накопленному
признаку: три подряд реальных 403, исчерпан бюджет запросов, потеря транспорта.

*Прецеденты:* НЭБ v3.1 — одна карточка без библиографии уничтожила экспорт целиком
(0 записей на диске); Пермь v9.2 — один узел остановил очередь на 23 из 184.

## 6. Барьер определяется по ответу сервера

- Реальный барьер: HTTP **401/403/429**, редирект на вход, пустое/обрезанное тело,
  страница-заглушка без полей карточки.
- **При HTTP 200 с разобранной карточкой `real_barrier` не выставлять никогда.**
  Фраза в теле страницы барьером не является (её может содержать обычный текст).
- **Сохранять тело и заголовки ответа**, вызвавшего барьер, в артефакты попытки.
  Без этого дефект невоспроизводим: регрессия на подставленной фразе ничего не доказывает.

## 7. Признак берётся из полей записи

Предмет и территория подтверждаются **заголовком и типом записи**. НЕ доказывают:
- формулировка поискового запроса (мы сами её задали);
- полнотекст карточки (слово может встретиться где угодно);
- название коллекции/фонда (напр. «Плановый архив…» — не доказательство, что дело картографическое).

Шаблоны — по морфологии, не по `\w*`: `карт\w*` ловит фамилию «Карташевых».
Слово без территориального якоря предмета не доказывает (§1.1-бис правил отбора):
`топограф*` в «топографии свадебных чинов» — не картография.

## 8. Хронология

`year_from` в scope **не задаётся** (§1.4). Верхняя граница — только как объявленный
`collect_until` + `collect_until_reason` с числом из разового замера; для библиотек не задаётся.

## 9. Версионирование

- Исторический выход **не меняется никогда**. Переоценка — только в новом каталоге.
- Имя каталога содержит версию и дату.
- Переоценка живого прогона — только после остановки писателя. Проверка «писателей нет»
  делается по **`run_loop.sh`** и lock-файлу, а НЕ по короткоживущему `run_catalog.py`:
  он живёт внутри попытки, и между попытками его закономерно не видно.

## 12. Решение человека выше машинного правила

Введено 2026-10-04 после случая: пакет Пермь v9.6 отсёк 7 записей, по которым пользователь
уже вынес решение «берём» (из 27 принятых в наборе осталось 20).

- Запись, по которой есть вердикт человека, **не переклассифицируется сборщиком** — ни в
  `scope_drop`, ни обратно в `needs_human`. Новое правило к ней просто не применяется.
- Файл решений человека принимается сборщиком **как вход**, ключ сопоставления — URL записи
  (номер строки листа проверки ключом быть не может: наборы пересобираются и нумерация смещается).
- Отказ человека помечается причиной `human_rejected`, а не машинной: из причины должно быть
  видно, кто принял решение.
- Если новое правило противоречит решению человека — правило не применяется, расхождение
  выносится пользователю.
- В отчёте приводится, сколько записей взято из решений человека и сколько машинных вердиктов
  ими отменено.
- Перед сборкой проверять **дату изменения брифа**: бриф может быть исправлен после решений
  пользователя (в этом случае так и было — правка внесена до передачи, но в работу попала
  прежняя редакция).

## 11. Признак обязан разделять набор

Введено 2026-10-04 после третьего замечания по одному пункту (Пермь v9.3 → v9.5 → v9.6).

- **Признак, одинаковый у 100 % записей, считается не выставленным.** Поле-вердикт
  (`needs_human`, `scope_verdict`) существует, чтобы делить набор: по нему фильтруют данные,
  распределяют ручную проверку и измеряют качество гейта. Одно значение у всех записей
  информации не несёт.
- Прецеденты: v9.4 — `needs_human=false` ровно у 14 записей, и все 14 оказались материалом,
  который брать нельзя (планы работы библиотеки, путеводитель, город как предмет);
  v9.5 — `needs_human=true` у 51 из 51, то есть весь набор переложен на человека.
  Оба раза признак не разделял.
- Вердикт **выводится из раздельных evidence** (subject / territory / level), а не ставится
  по умолчанию. Если классы уже вычислены — они обязаны влиять на вердикт.
- При `needs_human=true` обязательно поле причины (`needs_human_reason`): список без причин
  неразбираем человеком.
- В отчёте приводится **распределение вердиктов и причин с числами**. Если бесспорных записей
  в наборе действительно нет, это заявляется отдельной строкой с обоснованием.

## 10. Самопроверка перед сдачей (прогнать и приложить результат)

1. `csv_columns == 65`, имена колонок совпадают с эталоном;
2. `jsonl_valid == csv_rows`, битых строк 0;
3. `needs_human` и `evidence` присутствуют **в записях**, счётчик совпадает со сводкой;
4. сумма `keep + drops` равна входу (`conservation_delta == 0`);
5. матрица переходов `from → to` полная, с примерами;
6. регрессии из брифа пройдены и перечислены поимённо;
7. `ready_for_import=false`, Notion и онтология не затронуты;
8. поле-вердикт не одинаково у всех записей, распределение приведено (п. 11);
9. у каждой записи с `needs_human=true` заполнена причина;
10. ни одна запись с решением человека «берём» не лежит в отсеве (п. 12).

Несоблюдение любого пункта — пакет возвращается без разбора содержимого.
