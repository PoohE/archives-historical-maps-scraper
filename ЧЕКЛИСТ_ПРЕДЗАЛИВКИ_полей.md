# ЧЕК-ЛИСТ ПРЕДЗАЛИВКИ ПОЛЕЙ (обязательный гейт перед массовым внесением в Notion)

**Зачем.** Ошибки раскладки полей, найденные ПОСЛЕ заливки, стоят дорого (перепатч десятков тысяч
записей, OOM-перезапуски). Этот лист ловит их ДО записи. Вводится 2026-10-08 по указанию пользователя
после ГАПК (где постфактум пришлось разворачивать Название↔Описание на 15,5 тыс., чистить территорию,
скобки, типы, уровни, дубли земля/лес).

## Порядок (для КАЖДОГО нового пакета источника)
1. Сборка движка-раскладки, но **НЕ заливать**.
2. **Офлайн-аудит** по всему набору: все обязательные поля заполнены (0 пустых); пересечения
   предикатов классификации (напр. земля∩лес) = 0; чужая территория помечена.
3. **Образцы по КАЖДОМУ типу** (A1…C, серия/одиночка) — создать 2–3 карточки в Notion, дать ссылки.
4. **Показать пользователю заполненный чек-лист ниже** (значение + правило + флаг сомнения по полю)
   и получить подтверждение **по полям**.
5. Только после «ОК» — массовая заливка (потоково, резюмируемо, дедуп по фонд+опись+дело).
6. После заливки — повторный аудит полей + дублей на живой базе.

## Формат разбора пакета для показа пользователю (шаг 4, введено 2026-10-16 по образцу ГАКО)

Шаг 4 («показать пользователю») оформляется не произвольно, а по фиксированной структуре —
так разбор можно сравнивать между источниками и ничего не забыть. Разбор пакета ГАКО
(хендофф 13.10, разобран перед внесением 16.10) — эталонный пример применения.

1. **Арифметика пакета** — независимая третья проверка (см. память
   `feedback_arithmetic-check-needs-independent-value`): `accepted + needs_human +
   scope_drops` = объём, заявленный источником («N дел, выложенных порталом»/путеводителем).
   Два совпавших числа сами по себе не доказательство — нужно третье, внешнее.
2. **Дедуп по ключу** (Фонд+Опись+Дело) — 0 дублей, отдельной строкой.
3. **Дедуп/аномалии по ТЕКСТУ заголовка** — отдельно от ключа: одинаковые или обрезанные
   заголовки при разных номерах дел (источник режет длинные заголовки в списочной выдаче) —
   это не наша ошибка, но пользователь должен увидеть это явно, а не узнать постфактум.
4. **Таблица заполненности обязательных полей** — по каждому полю минимального профиля:
   сколько из N записей заполнено, что пусто и допустимо ли это (пусто ≠ ошибка, но нужно
   назвать вслух, а не молчать).
5. **Таблица DC Type / Тип источника по признаку** — Counter по полю-признаку источника
   (`kartograficheskiy_priznak` и т. п.) → DC Type. НЕ ставить один DC Type всем записям
   пакета по умолчанию — почти всегда среди «карт» затёсываются текстовые единицы (полевые
   записки, межевые книги).
6. **Одна карточка целиком, поле-в-поле** — не описание словами, а таблица
   «поле Notion → значение» на одном КОНКРЕТНОМ примере из пакета, с именами relation-целей
   (архив, территория), не url.
7. **Записи вне базовой территориально-временной модели** — если источник не только
   дореволюционный (губерния→уезд→волость), отдельно выявить записи другого периода/уровня
   (например советский район/сельсовет) и вынести решение пользователю, а не форсировать
   привязку и не отбрасывать молча.

Все семь пунктов — ДО заливки, одним сообщением пользователю. После «ОК» — заливка по
шагам 5–6 выше.

## Чек-лист по полям (отмечать ✓/✗ на образце и на распределении по набору)

| # | Поле | Правило | Частая ошибка (ловить!) |
|---|------|---------|--------------------------|
| 1 | **Название источника** | Короткое, содержательное: суть до первого «/», БЕЗ квадратных скобок, без хвоста «/Сост…/Рукописн.» | НЕ полный заголовок! (путали с Описанием); остались `[ ]` |
| 2 | **Описание** | ПОЛНЫЙ заголовок дословно — всё с карточки (составитель, техника, скобки) | было наоборот — короткое в Описании |
| 3 | **Фонд / Опись / Единица хранения** | Локатор. Для серии ед.хр. = перечень всех листов (+ полный список в теле, если не влезает) | дедуп ТОЛЬКО по (Фонд+Опись+Дело): номер дела НЕ уникален между описями |
| 4 | **Архив хранения** | Релейшн на верный архив (аббревиатура в конце названия справочника) | — |
| 5 | **Тип источника** | По ВИДУ документа: A3 межевой план (любой объект — дача/рудник/завод/село); A4 военно-топографич. (изд. топ.отдела/ген.штаба/корпуса); A6 план города/селения; A2 обзорная карта/атлас уезда, планшет волости; A5 тематические (лес, дороги); серия/лист | не дробить межевание по объекту; воен-топо ≠ A2; лесосеки = лес |
| 6 | **DC Type** | StillImage (карты/планы) / Text / Dataset | забыть проставить (пусто) |
| 7 | **Охватываемая территория** | По тому, что ИЗОБРАЖЕНО на карте. Чужая губерния/страна/общая карта → **отклонён** (не лить «по умолчанию в свою губернию»). Не путать уезд землемера с территорией. Не путать упомянутого владельца/смежную губ. с предметом | foreign просочились как «своя губерния»; «уездный землемер X» → X ≠ территория; сборные описи (общие/учебные карты) |
| 8 | **Современные регионы** | Релейшн, соответствует территории | — |
| 9 | **Административный уровень** | По ОБЪЕКТУ карты: дача / нас.пункт / волость / уезд / губерния. «Местность / район села / карта-схема» = Нас. пункт. НЕ ставить Губерния только потому, что уезд не распознался. **Губерния/уезд/волость в заголовке — часто ТОЛЬКО локатор** (место нахождения объекта или архивная рубрика), не охват документа: единичный план дачи/пустоши/надела/землепользования села — всегда «Дача», даже если уезд назван структурным полем заголовка (см. `catalog_guidelines_ru.md` §2.3) | fallback в «Губерния» для локальных карт; fallback в «Уезд» только потому, что название уезда есть в заголовке (найдено на ГАКО — 93/96 дел; подозревается и на уже внесённом РГИА ф.380) |
| 10 | **Язык** | Обычно Русский | забыть (пусто) |
| 11 | **Место хранения** | Полное имя архива + город | — |
| 12 | **Статус приёмки** | принято / кандидат (сомнение, needs_human, эвристика) / отклонён (не наша территория/тема) | — |
| 13 | **Статус доступа** | Очный архив без образов → «Только метаданные» | — |
| 14 | **Масштаб (знаменатель)** | Реальный или приближённый ПО ТИПУ (по линейке), помечен в «Оригинальный масштаб» как «приближённо по типу…». A4 воен-топо — мелкий конец (1:420 000 Спец.карта, 1:126 000 трёхвёрстка). Межевой план ≈1:8 400. Обзорные/дороги — можно пусто | приближённый не помечен; масштаб из врезки; единый формат «приближённо по типу …» |
| 15 | **Оригинальный масштаб** | Текст как на источнике ИЛИ «приближённо по типу «…» (~1:N  … в дюйме)» — ЕДИНЫЙ формат | разные форматы «приближённо» |
| 16 | **Автор / составитель** | Только имя (фамилия + инициалы), без «сост./копировал», без геоприлагательного и профессии, без техники; нет — пусто (не угадывать) | «ав Оханский Коверский», техника в авторе, срезанная фамилия на «-ский» |
| 17 | **Серия / массив** | Серия ТОЛЬКО если один документ разбит на листы (планшеты/части), каждый лист — отдельное дело. Разные объекты (участки/дачи/лесосеки разных мест) = поединично | слияние разных объектов; тематический массив (лес/воен-топо) — пометка в Примечаниях, не слияние |
| 18 | **Автор внесения / Дата внесения** | Агент / дата прогона | — |

## Проверки на уровне НАБОРА (до заливки)
- [ ] Пересечение предикатов классификации (напр. земля∩лес, тема∩тема) = 0 — иначе дубли при заливке.
- [ ] Территория: доля «своя губерния / свой уезд» vs «чужая/общая»; чужое → отклонён.
- [ ] Поменять способ обхода источника → сверить новое множество со СТАРЫМ по составу (не по числу!).
- [ ] Дедуп по (Архив+Фонд+Опись+Ед.хр.) против живой базы (SQL/REST) + отчёт вслух.
- [ ] Офлайн: 0 пустых обязательных полей (п. 1–13, 18); масштаб — где задаём.

## ⚠️ ГАПК — результат ПРЕДВАРИТЕЛЬНЫЙ (2026-10-09)
Внесение ГАПК (ф.279/716, ~16 тыс.) выполнено, но классификация по подстрокам заголовка даёт
**много ошибок** — нужна **сплошная ручная проверка с пользователем**, не считать закрытым.
Пойманные постфактум классы, которые фильтр пропускал (все → отклонён/кандидат вручную):
техчертежи оборудования (печи/прессы/турбины/машины), добыча (залежи/месторождения/прииски/
рудники/площади ископаемых), постройки/дома (фасады/корпуса/караулки; усадьба≠дом — усадьба
территория), чужие губернии/страны, природные объекты (пещеры), недособранные серии (ключ был
чувствителен к порядку слов). **Корень — модель не всегда понимает термины названий** →
нужна онтология терминов старинных карт (домен hgis). При проверке опираться на термин, не на регулярку.

Отклонено постфактум (пойманные классы, 2026-10-09, список НЕ исчерпывающий): техчертежи
оборудования **529**, добыча ископаемых **~760**, постройки/дома **166** (усадьба≠дом — усадьба
территория), чужие губернии/страны **254**; пещера→кандидат. Дубли после всех правок: **0**
(офлайн по журналам, ключ фонд+опись+дело). Проверку продолжать вручную с пользователем.
