# Codex: Пермь v9.3 — ложный `real_barrier` снова блокирует прогон (повтор дефекта E/E2)

Дата: 2026-10-02. Приоритет: **блокер** — tier B не стартует, собрано 23 карточки из 184.

## Воспроизведение (факты из выхода v9.2, не предположения)

Выход: `output/permkrai_catalog_maps_20261002_v9_2_node_list/`
Попытка: `attempts/20261002_145726_0adec27c/`

```
requests.jsonl:
  https://lib.permkrai.ru/robots.txt        → 200, 2633 байт
  https://lib.permkrai.ru/node/2794         → 200, 48955 байт
REPORT.json:
  stop_reason: "real_barrier:barrier_phrase"
  exit_code: 2,  requests: 2,  request_budget: 60
  completed_cards: 23  (из 184),  rows: 17
```

**Страница отдала HTTP 200 и 48 КБ контента — доступ есть.** Прогон остановлен целиком
из-за того, что в ТЕЛЕ карточки встретилась фраза-барьер. Это ложное срабатывание.

`node/2794` — обычная карточка библиотеки; фраза вида «доступ запрещён» встречается
в её тексте как часть описания/служебного блока, а не как ответ сервера.
Этот же узел ронял прогон в v9 (брифы E/E2 от 2026-10-02). Фикс не доехал.

## Что требуется

1. **Барьер определять по ответу сервера, а не по подстроке в теле.**
   Признак реального барьера: HTTP **401/403/429**, редирект на страницу входа,
   пустое/обрезанное тело, страница-заглушка без карточных полей.
   При **HTTP 200 с разобранной карточкой** `real_barrier` не выставлять **никогда**.
2. **Если фраза-эвристика остаётся** — только как `access_review` на **одной карточке**,
   без остановки очереди и без exit 2.
3. **Одна карточка не останавливает прогон** (это требование 0 из общего брифа
   «перевыпуск пакетов», оно до Перми не доехало): отказ на единице обработки →
   пометить единицу, записать причину, **перейти к следующей**. Останов всего прогона —
   только по накопленному признаку: три подряд реальных 403, либо исчерпан `request_budget`.
4. **Регрессия (обязательна):**
   - `node/2794` при HTTP 200 → карточка обрабатывается, прогон продолжается, `real_barrier` нет;
   - искусственный HTTP 403 → `access_review` на карточке, прогон идёт дальше;
   - три подряд 403 → останов с exit 2 (это поведение сохранить);
   - прежняя регрессия Перми 15/7/3 не ломается.

## Заодно в тот же пакет — §1.1-бис «слова-ловушки» (новое правило)

**Правило §1.1-бис:** ключевое слово само по себе предмета не доказывает. Проход только когда
картографический признак **и** территориальный якорь (губерния / уезд / волость / регион / дача /
объект межевания) подтверждены **полями самой записи** — заголовком и типом, **не полнотекстом**
карточки и не поисковым запросом. `топограф*` без территориального якоря — не картография.

**§1.2 уточнён:** путеводитель по городу, в том числе уездному, — `city_level`.

Это та же ошибка основания, что в аудите РГИА (`needs_human` у всех записей): признак брался
из запроса/полнотекста, а не из полей записи. Чинить одинаково в общем `scope_gate.py`.
