Дата: 2026-09-27. От: сессия полей/данных (Claude). Кому: Codex.
Статус: в очереди (числился строкой в КООРДИНАЦИЯ_прогоны_полнота-захвата — теперь явный бриф).

## Проблема
5 карточек ГПИБ в каталоге (`elib.shpl.ru`) сняты СТАРЫМ парсером не по правилам —
**дефект захвата, оффлайн не чинится**: «Описание» пустое 0/5, ссылки на скан нет 0/5,
в названиях склейка слов без пробелов («Картапочв Ярославскойгубернии»). Все 5 уже в Notion
со статусом «принято» → пере-прогон должен ПЕРЕЗАПИСАТЬ их по URL (мост `--update`), не плодить дубли.

- http://elib.shpl.ru/ru/nodes/115086 — Карта почв Ярославской губернии

- http://elib.shpl.ru/ru/nodes/58873 — Карта Смоленского, Калужского и Могилевского наместничеств

## Что снять (по КООРДИНАЦИЯ_прогоны_полнота-захвата §«Что обязательно снять»)
1. **Полный текст карточки дословно** → «Описание» (мастер-поле). Пусто = брак. + `card_html` в `extra` страховкой.
2. **Ссылка на скан/изображение**: прямой URL файла → поле 19; стабильный download/файловый URL → поле 63.
   У ГПИБ карты оцифрованы — скан должен быть.
3. **Название БЕЗ склейки слов** — восстановить пробелы (нынешние «Картапочв…» — брак токенизации парсера).
4. **Даты**: год издания / год сведений сырьём.
5. **Связанное издание** (поля 23–27) — если карта из атласа/книги/серии.
6. **Держатель оригинала** — ГПИБ (у некоторых карт возможен иной первичный держатель — снять как на карточке).
7. Масштаб/техника/территория — если явно на карточке.

## Раскладка и заливка (моя часть, после пере-прогона)
- v1.6-раскладку (`territory_resolve` территория/регион, типизация, DC Type, серии) применю оффлайн к `records_full.jsonl`;
- залью мостом `notion_upload_candidates.py --update` — дедуп по URL перезапишет 5 «принято» на месте
  (Описание/год/издание/скан не в PROTECTED_ON_UPDATE → зальются; статус «принято» сохранится).

## Готовность
Пере-прогон готов, если по 5 карточкам: «Описание» непусто, ссылка на скан есть, название без склейки,
даты и (если из издания) связанное издание сняты. Иначе — неполный скрап.
