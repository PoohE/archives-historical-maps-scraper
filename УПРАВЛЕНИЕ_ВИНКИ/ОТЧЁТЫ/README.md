# Шаблон отчёта Винки

Имя файла: `О-NNN_<источник>_<ГГГГ-ММ-ДД>.md` — номер совпадает с номером задания.
Промежуточный отчёт по долгому прогону: тот же файл, новый раздел «Срез на <время>».

```markdown
# О-NNN <источник> — <статус: ИДЁТ / ЗАВЕРШЁН / УПАЛ>

Задание: З-NNN. Машина: Винки. Дата: ГГГГ-ММ-ДД ЧЧ:ММ.

## Числа (посчитаны из файлов, не из вывода сборщика)

| Что | Значение | Откуда |
|---|---|---|
| Записей в наборе | | `wc -l records.jsonl` |
| Принято / прочитано | | `LATEST_REPORT.json` |
| Единиц обхода пройдено | | состояния на диске |
| Выход записан | <N мин назад> | mtime |

## Команда, которой запущено

Дословно, включая флаги и способ запуска (detached / run_loop).

## Живость (три признака)

- выход растёт: да/нет, последний прирост
- состояние обновляется: да/нет
- рабочий python в процессах: да/нет (между итерациями цикла — норма, что нет)

## Если упал

- код выхода, `stop_reason`
- последний URL
- что ответил сервер: HTTP-код, размер ответа
- **своя оценка: это дефект сборщика или блокировка источника?** (классификация
  в самом сборщике бывает неверной — у ПрБ v8 парсерная ошибка помечена как AccessBlocked)

## Находки и странности

Всё, что не сходится: пустые поля, подозрительные повторы, расхождение с заявленным
числом в задании, сломанная кодировка, незаявленные классы записей. Не править — описать.

## Файлы на диске

Полные пути + размеры. Что готово к переносу на Тинки.
```

## Чего в отчёте быть не должно

- «похоже, работает», «процесс идёт» без числа строк в файле;
- числа из памяти сборщика без сверки с файлом;
- предложения поменять параметры прогона (паузы, лимиты, территории) — это решение Тинки;
- внесённые самостоятельно правки кода.
