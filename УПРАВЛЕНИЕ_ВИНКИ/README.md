# Управление прогонами на второй машине (Винки)

Папка-канал между двумя сессиями Claude на разных компьютерах.
Заведена 06.10.2026.

## Распределение ролей

| | Тинки (старый ПК) | Винки (ноутбук ИГ РАН) |
|---|---|---|
| Роль | **главная**: планирует, принимает, решает | **исполнитель**: запускает прогоны |
| Память | ~0,4 ГБ свободно — прогоны не стартуют | хватает (47 ГБ) |
| Пишет в | `ЗАДАНИЯ/`, `ЖУРНАЛ_ЗАДАНИЙ.md`, весь проект, git, Notion | `C:\arch\` и `ОТЧЁТЫ/` — больше ничего |
| Контекст проекта | весь (правила, история, грабли, каталог) | только текст задания |

Разделение по зонам записи, а не по очерёдности — это снимает и конфликты Я.Диска,
и двойных писателей на один прогон.

## Почему синхронизацию НЕ надо ставить на паузу

Прогоны идут в локальной `C:\arch\` — вне зоны синхронизации. В папке Я.Диска у Винки
одна зона записи (`ОТЧЁТЫ/`), у Тинки — другая (`ЗАДАНИЯ/`, журнал, остальной проект).
Один файл двумя машинами не правится, значит Я.Диску нечего разрешать перезаписью.

Пауза вернётся в правила, только если решим гнать прогон прямо в папке Я.Диска:
`state.json` и `records.jsonl` переписываются каждые несколько секунд, и на таких файлах
Я.Диск делает конфликтные копии (инцидент 27.08, палеопочвенная БД).

## Протокол

1. Тинки создаёт `ЗАДАНИЯ/З-NNN_<источник>.md`, статус `НОВОЕ`, и строку в журнале.
2. Винки берёт задания со статусом `НОВОЕ` по порядку, выполняет дословно.
3. Винки пишет `ОТЧЁТЫ/О-NNN_<источник>_<дата>.md` по шаблону (`ОТЧЁТЫ/README.md`).
4. Тинки принимает **по артефакту, а не по докладу**: открывает отчёт, проверяет числа,
   состав полей, регрессии; ставит в журнале `ПРИНЯТО` или `ВОЗВРАТ` с причиной.
5. Готовые наборы переносятся в `output/<та же папка>/` на Тинки; крупные — ещё и в
   `C:\archive_backups\` вне зоны синка, с sha256 в коммит.

## Приёмка — что проверять

- **Состав, а не объём.** Совпадение числа строк не ловит обрезанный экспорт
  (прецедент: 15 колонок вместо 65 при нулевой дельте строк).
- **Признак живёт в записи, а не в сводке.** Флаг, существующий только в итоговом
  JSON-отчёте, бесполезен — по нему нельзя отфильтровать данные.
- **Все классы изменений заявлены** с числами и примером на класс.
