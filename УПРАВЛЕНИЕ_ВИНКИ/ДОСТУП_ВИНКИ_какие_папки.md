# Какие папки нужны Винки, а какие нет

Папка `D:\Yandex.Disk\History&Geography\БД\` содержит четыре проекта. Винки нужен **один**.

## Из папки «БД» — только один проект

| Папка БД | Винки | Почему |
|---|---|---|
| **`Поиск онлайн архив\`** | ✅ нужна (частично, см. ниже) | здесь прогоны |
| `Каталогизация\` | ❌ не нужна | зона сессии каталога (Notion), Винки туда не пишет |
| `Готовые списки\` | ❌ не нужна | итоговые наборы, их собирает Тинки |
| `Библиотечно-библиографическая классификация (ББК)\` | ❌ не нужна | справочник для каталогизации |
| `docs\` (в корне БД) | ❌ не нужна | — |

Три лишние папки лучше **не синхронизировать на Винки вообще** (Я.Диск → выборочная
синхронизация): меньше объём и нет возможности случайно тронуть зону каталога.

---

## Внутри «Поиск онлайн архив» — три разных режима доступа

### 1. ПИСАТЬ — ровно одна папка

```
УПРАВЛЕНИЕ_ВИНКИ\ОТЧЁТЫ\
```

Больше ни одного файла в папке Я.Диска Винки не правит. Это и есть защита от конфликтных
копий: Тинки в `ОТЧЁТЫ\` не пишет.

### 2. ЧИТАТЬ (не менять) — задания и правила

| Путь | Зачем |
|---|---|
| `УПРАВЛЕНИЕ_ВИНКИ\ЗАДАНИЯ\` | откуда берутся задания |
| `УПРАВЛЕНИЕ_ВИНКИ\README.md`, `ОТЧЁТЫ\README.md` | протокол и шаблон отчёта |
| `ПЕРЕНОС_ПРОГОНОВ_НА_ВТОРУЮ_МАШИНУ_2026-10-06.md` | что ставить, что запускать |
| `DECISIONS.md` | правила проекта (в т.ч. запрет `verify=False`) |
| `АНАЛИЗ_ВСЕХ_АРХИВОВ\ЗАМЕТКИ_по_пройденным_архивам.md` | грабли прогонов |
| `РЕГЛАМЕНТ_приёмки_пакета_сборщика.md` | по каким критериям принимается результат |

Суммарно — единицы мегабайт.

### 3. КОПИРОВАТЬ в локальную `C:\arch\` — и работать только оттуда

Прогон **не запускается из папки Я.Диска**: файлы состояния переписываются каждые секунды,
и синхронизация разрешает расхождение перезаписью или конфликтной копией.

```
C:\arch\
    scripts_rosarchive\     1 МБ   сборщик УИАД, cdp.py, parsing.py, run_detached.ps1
    scripts_gapk\           1 МБ   сборщик ГАПК
    scripts_review\         1 МБ   аудиты и свёртки
    scripts\modules\        4 МБ   общие модули (territories.py, registry.py, скраперы)
    output\
        rgia_fund380_handoff_20261003_v3_1\    1,2 МБ   пакет ф.380 (код)
        rgia_fund380_20261003_v3_1\            173 МБ   его состояние и данные — для продолжения
        uiad_rgvia_maps_20261004\              165 МБ   состояние и данные УИАД
        rosarchive_rgvia_20261004\fund_ids.json         идентификаторы фондов РГВИА
```

Итого ~340 МБ. Можно урезать почти вдвое: в `rgia_fund380_20261003_v3_1` основной объём —
`scope_drops.jsonl` (журнал отсева, ~145 МБ), для продолжения прогона он не нужен. Тогда
обязательны: `fund380_opis_state\`, `records.csv`, `records_full.jsonl`, `run_scope.json`,
`fund_inventory.json`, `LATEST_REPORT.json`.

### Что НЕ копировать

| Не копировать | Почему |
|---|---|
| `output\gapk_maps_20261005\` | ГАПК завершён, 19 441 запись уже у нас |
| `output\prlib_catalog_full_handoff_20261006_v8\` | ПрБ v8 падает на разборе карточки, ждёт фикса Codex — задания по нему нет |
| остальные ~150 папок `output\` | архив прошлых прогонов, для работы не нужен |
| `сourse\`, `скрины архивов\`, `staging\`, `input_*\` | материалы прошлых разборов |

## Итог одной фразой

На Винки синхронизируется **только `БД\Поиск онлайн архив\`**; из неё Винки пишет
**только в `УПРАВЛЕНИЕ_ВИНКИ\ОТЧЁТЫ\`**, а работает в локальной `C:\arch\`, куда скопировано
~340 МБ (скрипты + состояния двух незакрытых прогонов).
