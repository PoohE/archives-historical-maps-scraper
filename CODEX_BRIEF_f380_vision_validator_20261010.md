# Бриф Codex: валидатор самопроверки для распознанных описей ф. 380

Дата: 10.10.2026. Ставит: claude-6a (сессия сбора). Источник: РГИА ф. 380, распознавание
Vision'ом описей 21 (Пермская губ.) и позже 37 (Ярославская губ.).

---

## 1. Зачем это нужно

Методика распознавания исторических источников (`~/.claude/skills/historical-handwriting/`)
требует после каждой порции прогонять три правила самопроверки документа — они ловят ошибки
чтения без эталона и без человека:

1. **Арифметика документа.** `udobnoy + neudobnoy = vsego`, с переносом единиц: у ф. 380 это
   1 десятина = 2400 квадратных саженей. Значения хранятся как строки вида `"21457/1979"`
   (десятины/сажени). Несходящаяся строка помечается, не правится.
2. **Сквозная нумерация.** Поле `n` (№ по порядку) обязано идти без пропусков внутри одного
   уезда/раздела; разрыв — сигнал пропущенной записи.
3. **Словарь закрытых полей.** `scale_raw` — масштаб (ограниченный набор формулировок: «N
   верст», «N саж.», «1/N»); значение вне шаблона — флаг.

Сейчас это делается вручную на каждой записи (см. пример разбора записи № 425 в
`РЕВИЗИЯ_страниц_для_распознавания_ф380_20261010.md` — две ошибки чтения найдены арифметикой,
одна осталась неразрешённой и помечена на сверку человеком). На объёме 109+ листов ручная
проверка не масштабируется — нужен скрипт.

## 2. Формат входа

JSONL, одна запись на строку. Пример (реальная запись из уже распознанного):

```json
{"n": 425, "katalog": "10080", "dacha_n": "251", "title": "Планшеты Юксъевского и Пелымского сельских обществ...", "planov": "10 планшетов", "scale_raw": "100 саж.", "udobnoy": "21457/1979", "vsego": "21497/2380", "podlinnik": "Подлин. 1856", "note": "...", "razdel": "в) Крестьянские земли и леса", "list": "120", "scan": 124, "needs_human": true, "needs_human_reason": "...", "arith_ok": true}
```

Поля: `n` (int, № по порядку), `katalog` (str, № хронологического каталога), `dacha_n` (str,
может быть пустым), `title` (str), `planov` (str, свободный текст), `scale_raw` (str),
`udobnoy`/`vsego` (str вида `"ДЕСЯТИНЫ/САЖЕНИ"` или пусто — пустое поле это не ошибка,
удобная земля не всегда записана), `podlinnik` (str), `note` (str), `razdel` (str, одна из
семи рубрик описи — список ниже), `list`/`scan` (str/int — лист описи и номер скана),
`needs_human`/`needs_human_reason` (bool/str — уже проставлены на этапе чтения, если
распознающий сам отметил сомнение; скрипт их не трогает, только добавляет новые отметки),
`arith_ok` (bool|null — уже может быть частично заполнено, скрипт пересчитывает и может
переопределить).

Семь рубрик `razdel` (ровно эти строки, с префиксом буквы):
```
а) Юридические документы
б) Административные карты, планы и проч.
в) Крестьянские земли и леса
г) Оброчные статьи, запасные и свободные земли
д) Казенные леса и корабельные рощи
е) Земли общего и чресполосного владений
ж) Предположения и проекты
```

## 3. Что сделать

Скрипт `scripts_rgia/validate_vision_records.py` (или по вашей конвенции именования —
сверить с существующими `scripts_rgia/*.py` в этом репозитории на стиль). Запуск:

```
python -B scripts_rgia/validate_vision_records.py <входной.jsonl> [--out <папка>]
```

### 3.1. Арифметика
Распарсить `udobnoy` и `vsego` как `(десятины, сажени)`. Если оба поля заполнены:
`neudobnoy_дес, neudobnoy_саж = vsego - udobnoy` с переносом по модулю 2400 (как в десятичных
дробях — сажени могут давать "заём" у десятин, как в уже разобранном примере описи ф. 380 оп.
39: `135092` при проверке, а прочитано `135098`). Если разница отрицательна или не считается
(поля пустые/нечисловые) — `arith_ok = null`, не `false`. Если считается и равенство не
сходится — `arith_ok = false` плюс `needs_human_reason` дописывается (не затирается, если уже
есть текст — добавить через `; `) строкой вида
`"арифметика не сходится: udobnoy+neudobnoy(расч.)=X, а vsego=Y"`.

### 3.2. Сквозная нумерация
Группировать записи по `razdel` (внутри одного прогона это обычно один уезд за раз, но
скрипт должен группировать явно, не полагаться на порядок файла). Внутри группы сортировать
по `n`, искать разрывы. Разрыв — `n` отсутствует между минимумом и максимумом встреченных.
Не считать разрывом, если следующая по номеру запись реально отсутствует в описи
по независимой причине (архивная помета «Выбыло» встречается в скане, но в наших JSONL её
скорее всего нет как поля — не выдумывать такое поле, если его нет во входе; разрыв просто
попадает в отчёт, решение за человеком).

### 3.3. Словарь масштабов
Регулярка допустимых форм `scale_raw` (дополнить по факту, это стартовый набор):
```
^\d+(\.\d+)?\s*(саж\.?|сажен(ей|и)?)$
^\d+(\.\d+)?\s*(верст(а|ы|)?|вер\.?)$
^1\s*/\s*\d+$
^$
```
(пустая строка допустима — не все записи имеют масштаб, см. запись 424 в уже разобранном
примере — «То же», без своих данных). Значение вне списка — не ошибка типа `false`, а
`needs_human_reason` дописывается `"масштаб вне словаря: '<значение>'"`, поле `arith_ok` не
трогается этим правилом.

## 4. Что на выходе

1. **Тот же JSONL**, но с дополненными `needs_human`/`needs_human_reason`/`arith_ok` (не
   терять исходные значения этих полей, только дописывать новые основания через `; `).
2. **`VALIDATION_REPORT.json`** в папке вывода:
   ```json
   {
     "input": "...",
     "total_records": N,
     "arith_checked": N, "arith_ok": N, "arith_failed": N, "arith_skipped": N,
     "numbering_gaps": [{"razdel": "...", "gap_after_n": 425, "next_n": 428}],
     "scale_out_of_vocab": [{"n": 423, "scale_raw": "48 верст(?)"}],
     "generated": "YYYY-MM-DD HH:MM"
   }
   ```
3. Печать в консоль краткой сводки (аналогично другим скриптам проекта — см. стиль
   `scripts_rgia/apply_opis39_sections.py` или `extract_uezd_slice.py`).

## 5. Гейт готовности (обязательно перед сдачей)

Тестовый вход: 8 уже распознанных записей Чердынского уезда,
`output/rgia_f380_op21_cherdyn_vision_20261010/records.jsonl` (в этом же репозитории).
Ожидаемый результат на нём:
- запись 425 должна дать `arith_ok: true` (сходится по саженям — 401 и там, и там; это
  известный предельный случай методики, где арифметика НЕ различает два варианта чтения
  десятин — она не обязана его разрешить, достаточно что `arith_ok=true`, расхождение с
  ручным эталоном в `needs_human_reason` уже прописано заранее мной и не должно быть
  перезаписано, а дополнено);
- `ruff check` чист;
- скрипт реально запускается на этом файле и печатает отчёт — приложить фактический вывод
  команды к сдаче, не пересказ.

## 6. Чего НЕ делать

- Не определять правильное значение самостоятельно, не «чинить» несходящиеся записи —
  только помечать.
- Не трогать смысловые поля (`title`, `katalog`, `podlinnik` и т.п.) — только служебные
  (`needs_human`, `needs_human_reason`, `arith_ok`).
- Не писать в чужие файлы и папки, не трогать `output/` других пакетов, `git add -A`
  запрещён (в репозитории много незакоммиченного чужого) — коммитить только свои файлы
  поимённо, если вообще коммитить (решение по коммиту — за принимающей сессией).
- Не считать себя исполнителем самого распознавания — вход уже готовый JSONL, вы его не
  создаёте и не правите смысл записей.
