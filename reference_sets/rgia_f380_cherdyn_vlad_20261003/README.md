Пересечений с эталоном — **ноль**: наши 18 дел из других фондов.

Две причины разрыва, и важна вторая:
1. **Техническая** — пагинация в пакете ф.380 v2 не работала: у оп.21 37 страниц дерева, взята
   одна. Лечится пакетом v3 (параметр `page`, не `nPage`).
2. **Принципиальная** — онлайн-каталог fgurgia.ru даёт уровень **дела описи**, а эталон доведён
   до **внутреннего содержания описи**: отдельные дачи с масштабом и площадью. Этого уровня
   в каталоге нет вообще, никакой обход его не достанет — только чтение самой описи.

Отсюда вывод для межевых фондов (РГИА ф.380, ф.1350; РГАДА ф.1354): обход каталога
принципиально беднее описи, и объём даёт распознавание описей, а не sweep по каталогу.

## Как применять

1. Распознать ту же опись (ф.380 оп.21, раздел по Чердынскому уезду) своим способом
   (Claude Vision по изображениям описи — так уже сделаны ф.1356 оп.2 и оп.3).
2. Сверить позиция к позиции по ключу `№ хронологического каталога` (он уникальнее
   названия: названия типовые — «Тоже», «К деревне Ульвы»).
3. Считать раздельно: пропуски (есть у человека, нет у ИИ), лишние, расхождения в масштабе,
   площади, дате, № дачи.
4. Решение по результату: достаточно ли выборочного контроля человеком или нужна полная
   ручная сверка каждой описи.
