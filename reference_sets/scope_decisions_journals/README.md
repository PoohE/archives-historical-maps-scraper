# Журналы решений гейта охвата — то, что НЕ восстанавливается повторным прогоном

Отсев по источникам бывает двух видов, и защищать их надо по-разному.

**Сырой отсев** (`output/*/scope_drops.jsonl`, ~76 тыс. записей, 114 МБ) — результат работы
автоматического гейта. Воспроизводится: прогнать сбор заново, правила те же, отсев тот же.
Под git не идёт, живёт на Я.Диске.

**Журналы решений** (эта папка, 1,7 МБ) — решения, принятые руками: что именно считать вне
охвата и почему. Повторный прогон их НЕ вернёт. Поэтому они здесь, под git.

## Что здесь

| файл | что это |
|---|---|
| `rgia_f380_queue_out_of_scope_2137.csv` | очередь ф. 380: 2137 записей признаны вне охвата, у каждой мотивировка — по какому разделу описи 39 или по оглавлению описей 38/40/41 |
| `rgia_f380_queue_ours_158.csv` | обратная сторона той же расчистки: 158 записей наших четырёх губерний с указанием раздела |
| `prlib_subject_gate_381_decisions.json` | предметный гейт ПрБ: разбор очереди «предмет не подтверждён» по классам (делопроизводство/открытки/периодика отклонены, гезеттиры/переписи/писцовые книги приняты) |
| `permkrai_scope_reassess_drops.jsonl` | переоценка Пермской по текущим правилам |
| `neb_manual_drops.csv` | ручной отсев НЭБ |
| `rgia_f380_op37_restore_report.json` | возврат описи 37 из отсева — отчёт о том, как ложная потеря была найдена |

## Зачем это хранить

Прецедент уже был: гейт отсеял **всю опись 37** (1129 дел) по аннотации
«Черниговская-Ярославская», приняв алфавитный диапазон за чужой регион. Ярославская
губерния была внутри. Нашли это только потому, что сырой отсев сохранился и его можно
было пересмотреть (`scripts_rgia/restore_opis37_from_drops.py`).

Отсюда правило: **отсев — не мусор, а материал для пересмотра**. Когда меняются правила
охвата или находится ошибка в аннотациях источника, первым делом перепроверяется он.
Журналы решений нужны, чтобы при таком пересмотре было видно не только ЧТО отсеяли,
но и ПОЧЕМУ — иначе работа по мотивировке делается заново.
