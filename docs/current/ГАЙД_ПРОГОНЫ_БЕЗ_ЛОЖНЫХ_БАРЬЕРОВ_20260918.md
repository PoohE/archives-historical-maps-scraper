# Гайд: большие прогоны без ложных барьеров (Codex + Claude)

Дата: 2026-09-18. Повод: прогон `prlib_catalog_full_20260917_v1` остановился на
1/294 запросов с вердиктом `authentication_or_login_form_unresolved`, хотя барьера
не было — страница HTTP 200 «По вашему запросу нет результатов» (пустой хвост
выдачи) с вечной формой «Войти» в шапке. Проверено вручную в чистом браузере и
зафиксировано фикстурой `tests/fixtures/prlib_search_empty_tail_20260918.html`.

## 1. Главный принцип

**«Обход барьера» и «распознавание конца данных» — разные вещи.**
Политики (Codex и Claude) запрещают первое и не ограничивают второе.
Большинство тупиков больших прогонов — это НЕ барьеры, а неопознанные концы
выдачи. Их чинят классификацией, а не обходом.

Не является обходом: соблюдение robots.txt и crawl-delay; задержки и лимиты
GET; распознавание «ничего не найдено» как штатного конца; resume/чекпойнты;
дедуп; сверка JSONL↔CSV. Является обходом (не делаем никогда): пробив CAPTCHA;
подбор/передача чужих сессий и cookies; маскировка под браузер для обхода
защиты; игнорирование 403/429; парсинг из-под личной авторизации то, что
анонимно закрыто.

## 2. Контракт: пять вердиктов classify_stop

Модуль: `scripts/modules/classify_stop.py` (тесты `tests/test_classify_stop.py`,
10 шт., включая реальную фикстуру ложного барьера и свип по 36 сохранённым
страницам прогона). Все сборщики после каждого ответа страницы выдачи зовут
`classify_response(...)` и ветвятся ТОЛЬКО по вердикту:

| Вердикт | Что значит | Действие сборщика |
|---|---|---|
| `more_pages` | есть результаты и следующая страница | продолжать пагинацию |
| `reported_end` | подтверждённый конец выдачи (последняя страница с результатами ИЛИ пусто + явный маркер «нет результатов») | закрыть запрос, перейти к следующему |
| `ambiguous_empty` | пусто там, где ждали данные, без маркера конца | пометить запрос `unverified`, стоп по запросу без повтора; в coverage — честный статус |
| `real_barrier` | 401/403/429, CAPTCHA-виджет, redirect на login, сильная фраза запрета | остановить прогон, эскалация человеку/Claude-сессии; НЕ обходить, НЕ ретраить |
| `transport_error` | сеть/таймаут/не-HTML/неожиданный redirect | политика ретраев транспорта (как настроена в пакете) |

**Железное правило:** наличие `input[type=password]` / формы логина / кнопки
«Войти» в решении НЕ участвует (это элемент оформления, присутствующий на
каждой странице). Классификатор фиксирует его информационным сигналом
`login_form_present_ignored` — для наблюдаемости, не для вердикта.

Новый источник (архив/библиотека) = новый `SourceProfile` (item-паттерн,
маркеры конца, селекторы CAPTCHA, имя параметра страницы) — конфиг, а не новый
классификатор и не новый сборщик.

## 3. Как формулировать задачи Codex (чтобы политика не резала легитимное)

| Вместо (триггерит запрет) | Писать (та же работа, корректно) |
|---|---|
| «пройди/обойди барьер», «продави пагинацию несмотря на…» | «дойди до подтверждённого конца выдачи каждого запроса (reported_end по classify_stop)» |
| «игнорируй форму логина» | «форма логина не участвует в решении об остановке (контракт classify_stop §2)» |
| «обойди пустые страницы» | «пустая страница с маркером „нет результатов" = штатный конец запроса» |
| «ретрай до победы» | «ретраи только для transport_error по политике транспорта; real_barrier — стоп и эскалация» |
| «скачай всё» | «собери метаданные закреплённой области scope.json, соблюдая robots/задержки/лимит GET» |

В каждый handoff-пакет включать явный блок: «Барьеры не обходятся. real_barrier
останавливает прогон и возвращается человеку. Конец выдачи распознаётся
classify_stop и барьером не является».

## 4. Настоящие барьеры — маршрут эскалации, не код

`real_barrier` — это точка маршрутизации: (1) Claude-сессия вручную проверяет
страницу в чистом браузере (ложный/настоящий?); (2) настоящий → официальный
канал: API источника, платная услуга/прейскурант (ПрБ: Правила ЧЗ п. 3.1.8),
читальный зал, письмо держателю фонда; (3) в код не возвращается ничего,
кроме честной записи в coverage. Пермская библиотека — пример транспортного
тупика (TCP до хоста не открывается из-под VPN): решается split tunneling,
не скриптом.

## 5. Протокол двух сессий (Codex = код, Claude = сеть и диагноз)

Роли: **Codex** пишет и правит детерминированный код (сборщики, classify_stop,
профили источников, тесты, frozen-пакеты) — без сети. **Claude** исполняет
сетевые прогоны по INSTRUCTIONS.md, следит за лимитами, диагностирует остановки
(вплоть до ручного браузера) и возвращает Codex воспроизводимые артефакты.

Цикл (повторяется до query_scope_complete):
1. **Codex → Claude:** handoff-пакет `output/<источник>_<задача>_handoff_<дата>_vN/`
   (INSTRUCTIONS.md + run_*.py + frozen/ + manifest SHA-256 + локальные тесты N/N).
2. **Claude:** прогон строго по инструкции (бюджеты, resume, один процесс);
   остановка → триаж по вердикту: `request_budget` — продолжить той же командой;
   `real_barrier` — ручная проверка страницы в браузере; ложный барьер —
   НЕ чинить на живом прогоне.
3. **Claude → Codex:** отчёт-возврат в `output/`: REPORT.json попытки + диагноз
   («страница X: ожидалось А, получено Б») + **захваченная сырая фикстура**
   спорной страницы в `tests/fixtures/<источник>_<случай>_<дата>.html` (сырой
   HTTP-ответ, не браузерный DOM) + при необходимости готовый тест-регрессия.
4. **Codex:** правит рабочие модули под регрессию (фикстура обязана проходить),
   гоняет локальные тесты (из `tests/`: `python -m pytest`), собирает новый
   frozen-пакет vN+1.
5. **Claude:** продолжает прогон новым пакетом; накопительное состояние
   (`prlib_query_state` и т.п.) сохраняется между версиями пакета.

Границы, чтобы сессии не толкались: Codex не запускает сеть; Claude не правит
frozen/ и не меняет scope; рабочие `scripts/modules/` правит одна сторона за
цикл (передача — через PROGRESS.md); фикстуры и тесты — общая зона, но файл
пишет тот, кто его вводит; git-коммит смысловой порцией сразу после зелёных
тестов (правило координации из AGENTS.md).
