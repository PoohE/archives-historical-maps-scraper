# Задание скриптовой сессии: принять OCR-модуль карт в работу

**Кому:** соседняя сессия, пишущая скрипты в репо «Поиск онлайн архив».
**От:** сессия разбора полей каталога (РНФ, ветка выборки).
**Дата:** 2026-09-23. **Модель для интеграции/маппинга:** Opus 4.8.

## Зачем (цель, для кого)
Второй слой данных источника — **само изображение карты** (скан по ссылке/в просмотрщике),
не только текст карточки. Многие карточки онлайн-библиотек НЕ содержат ключевых полей
(**масштаб, год**), а на самом скане они есть. Задача: автоматически извлекать их с
изображения карты как **КАНДИДАТОВ** для (1) ручного поиска приёмщика по карточкам и
(2) чернового заполнения полей каталога. Канон разрешает: масштаб/проекция/меридиан/техника —
с «подтверждённой надписи ОСНОВНОЙ карты», легенда — источник для «Типов отображаемых объектов».

## Что уже есть (не переписывать — расширять)
- `scripts/modules/image_ocr_candidates.py` — EasyOCR (ru+en) по ROI: вытягивает `1:N` масштаб +
  помечает блоки автор/издание; пишет ТОЛЬКО `ocr_candidates.json` (candidate-only, sha256,
  провенанс, оговорки). Требует: скачанный образ, **ручной ROI**, локальные модели EasyOCR.
  Сам помечен: «missing-field reconciliation not yet integrated».
- `scripts/modules/cartographic_enrichment.py` — `convert_scale()` (явный `1:N`, км/м в см,
  **вёрсты в английском дюйме** → знаменатель с формулой и ссылками на единицы) + легенда →
  «Типы отображаемых объектов» (44) через `object_types.json`; потребляет **approved main_map**
  observations, иначе — вопрос на проверку.

## Что построить (договорённости Д16/Д17)

### 1. Авто-триггер OCR (гейт стоимости — ключевое)
Запускать OCR **автоматически, ЕСЛИ выполнены ВСЕ три**:
1. есть ссылка на изображение карты (поле 19 / reol / просмотрщик);
2. источник **картографический** — тип A1–A6 / DC StillImage / маркер «карта/план/атлас/чертёж»
   в названии (НЕ текстовый документ);
3. в карточке **отсутствует масштаб ИЛИ год**.

Иначе — только **по требованию** (текущий CLI-режим оставить). Гейт снимает проблему стоимости:
OCR не гоняется на всём прогоне, только там, где карта и пробел в ключевых полях.

### 2. Захват образа
- скрапер должен сохранять **прямой URL скана** (поле 19). Проверить/дополнить `prlib_card`
  (`extra.direct_map_image_url`, `gallery_urls`) и прочие адаптеры;
- авто-скачивание образа во **временную ASCII-папку** (Windows: путь без пробелов/кириллицы —
  см. `rules/scripting.md` «Playwright/браузерные…»), считать sha256, после работы — убрать/перенести.

**Прямой URL скана по источникам (механики):**
- **РГАДА** — на странице-просмотрщике описи сканы лежат в атрибутах тега `<img>`:
  `data-largeim="1/<опись>/<NNNN>.jpg"` — **максимальное разрешение** (префикс `1/`);
  `data-large="2/…"` — пониже. Полный URL = `{базовый путь страницы просмотрщика} + {значение
  data-largeim}`. Имя папки описи — предпоследний сегмент пути (`…/1209-opis_231i/0037.jpg`).
  Референс механизма — `okolobaxa/rgada-downloader` (C#/.NET, `PageParser.cs`): **брать логику
  (~30 строк порта на Python), не код**. ⚠️ Проверить, ведёт ли каталожный URL описи
  (`poisk/index2.php?str=…`) на страницу с `data-largeim`, или нужен переход на просмотрщик;
  утилита качает ВСЮ опись постранично — нам для OCR нужен таргетный лист карты (тот же механизм,
  выбирая нужные страницы).

**Прямой URL скана — ГПИБ (elib.shpl.ru):** тайловый просмотрщик (`mode/grid/page/N/zoom/N`).
Полное изображение — через IIIF: у узла обычно есть `info.json` → собрать
`{image_base}/full/full/0/default.jpg` (или максимальный доступный размер), либо download-эндпоинт
страницы. Для многолистовых — брать лист карты (не обложку). Предусловие: ГПИБ-адаптер сначала
должен СНЯТЬ этот URL в поле 19 (сейчас не снимает — см. задание адаптеров, раздел ГПИБ).

### 3. Расширить `image_ocr_candidates.py`
- добавить кандидат **ГОД**: 4-значный год, правдоподобие **1600–1939**;
- добавить кандидат **ТЕКСТОВЫЙ МАСШТАБ** («N вёрст в дюйме» и пр.) → передавать в
  `cartographic_enrichment.convert_scale()`;
- **авто-режим: ROI = весь кадр** (без ручного выбора врезок) → все находки идут как
  **candidate + review** (принадлежность основной карте подтверждает человек);
- сохранить текущее: `1:N` масштаб, флаги автор/издание.

### 4. Reconciliation — интеграция кандидатов в маппинг (сейчас ОТСУТСТВУЕТ)
Влить OCR-кандидатов в маппинг карточки. Целевые поля (канон):
| С изображения | → Поле каталога | Статус |
|---|---|---|
| масштаб (цифр./пересчит.) | «Масштаб (знаменатель)» (29) | candidate |
| масштаб (текст) | «Оригинальный масштаб» (30) | candidate |
| год (дата на карте) | «Год создания (нижняя)» (13) → кормит формулу «Год источника» | candidate |
| автор/ведомство карты | «Автор / составитель» (11) | candidate + флаг |
| легенда — список объектов | «Типы отображаемых объектов» (44) + текст в «Описание» | candidate |

ВСЁ — со статусом **candidate + review-флаг + провенанс** (source_url, sha256, engine/version, ROI).
**Никогда** не писать как принятое; заливка в Notion — только санкционированный мост
`notion_upload_candidates.py` (канон п.5), не MCP.

## Ограничения / канон (обязательно)
- candidate-only; принятые метаданные OCR не пишет; визуальная сверка обязательна (канон OCR);
- OCR confidence ≠ факт; **не выводить масштаб из размеров скриншота/линейной шкалы**;
- provenance + sha256 у каждого кандидата;
- Windows: образ и промежуточные файлы — ASCII-temp, потом move; скрипты писать **файлом** (`Write`),
  не heredoc; `fix_stdout()` первой строкой;
- писать можно **только в своём репо** «Поиск онлайн архив»; в `Каталогизация`/`Ontology` не писать.

## Гейт готовности (определение «сделано»)
1. `ruff check` чист;
2. реальный прогон на ≥1 карте с образом → `ocr_candidates.json` + кандидатные поля заполнены;
3. регресс: карточка-карта без масштаба/года, но с картинкой → авто-триггер сработал, поля-кандидаты
   (29/30/13/11/44) появились со статусом candidate + провенанс; текстовый документ без картинки →
   OCR НЕ запустился.

## Дополнение: детектор серийности (поля 52/53) — договорённость Д18

Отдельная от OCR фича, **тому же исполнителю**. Всё — **candidate + review**; новую серию
**авто НЕ создавать** (экспертный гейт, канон поле 52: связь только с существующей записью
справочника «Серийные массивы», спорное — вопрос эксперту).

### Детектор A — по логике названия (одна карточка; в enrichment/маппинге)
- серийные маркеры: «Лист N», «Том N», «Вып. N», «№ N», «Ч. N» + названия серий по **алиасам**
  справочника «Серийные массивы»;
- совпало со справочником → кандидат **52** + номер из маркера → **53**;
- маркер серии есть, а серии в справочнике нет → флаг **«кандидат в новую серию»** (не создавать),
  название+номер → кандидатное примечание → экспертный гейт.

### Детектор B — по кластеру прогона (в стадии review-run; нужен весь прогон)
- нормализовать «стебель» названия (ниж. регистр, ё→е, снять номера/маркеры и варьирующийся топоним);
- кластер **≥3** карточек с общим стеблем, различающихся только номером/территорией → сигнал
  «серийный массив» (напр. «План дачи №…», «Карта … уезда» по разным уездам);
- каждому члену — кандидат **52** (обнаруженный массив) + **53** (номер) → review; массива нет в
  справочнике → **предложение эксперту** завести;
- **оговорка:** одноимённость ≠ всегда серия → порог ≥3 + обязательный review, авто-принятия нет.

### Где живёт
- детектор A — enrichment/маппинг (по одной карточке);
- детектор B — **новый шаг/модуль в стадии review-run** (кросс-прогон), НЕ трогая логику
  фильтра `decide()`/`triggers.py` (период/территория/картографичность остаются как есть).

### Гейт готовности детекторов
`ruff` → прогон на реальном наборе (напр. `output/prlib_catalog_full_20260917_v1`) → кластеры и
кандидаты 52/53 появились со статусом candidate + основание; одиночные (уникальные) названия в
серию НЕ попали.
