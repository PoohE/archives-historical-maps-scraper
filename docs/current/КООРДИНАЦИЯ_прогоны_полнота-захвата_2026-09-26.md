# Координация прогонов: полнота захвата (чтобы не потерять данные)

Дата: 2026-09-26. От: сессия полей/данных (Claude). Кому: сессии-с-прогонами (РГАДА готова,
РГИА идёт) + Codex (пишет адаптер Пермской краевой библиотеки, lib.permkrai.ru).

## Главный принцип (один, для всех)
**`records_full.jsonl` = источник истины и должен быть ПОЛНЫМ.** Раскладку по полям каталога v1.6
можно применить ОФФЛАЙН в любой момент (пример — `adapters_v16_relayout`). Поэтому:
- **раскладка/маппинг — вторичны и переделываемы без сети;**
- **данные теряются ТОЛЬКО если их не снял сам скрап** → тогда нужен дорогой пере-прогон
  (случай ГПИБ: пустое «Описание» + нет ссылки на скан = 5 записей на пере-сбор).

Вывод: **лучше снять с карточки ИЗБЫТОЧНО, чем потом пере-прогонять.** Маппинг я/Codex доведём
оффлайн; ваша задача на прогоне — ничего не потерять.

## Что ОБЯЗАТЕЛЬНО снять на прогоне (невосстановимо оффлайн)
Для каждой карточки в `records_full.jsonl` (в `record` и/или `record.extra`):
1. **Полный текст карточки дословно** → станет полем «Описание» (мастер-поле поиска). ГЛАВНОЕ.
   Пусто = брак (как ГПИБ). Плюс сырой блок/HTML карточки в `extra.raw_*` — страховка для любой
   будущей раскладки.
2. **Ссылка на скан/изображение**: прямой URL файла → поле 19; стабильный download/файловый URL →
   поле 63. Без них не работает OCR-слой и ложно «нет цифровой копии».
3. **Нативные шифры**: архив — Фонд/Опись/Дело отдельными полями (не только строкой); библиотека —
   все шифры карточки (полочный/ББК/инвентарный/ID).
4. **Даты как на карточке**: год издания, год сведений/состояния, диапазоны — сырьём (нормализацию
   в поля 13/14/14а сделает раскладка).
5. **Серия/том**: маркеры «Т./Вып./Лист/№» и название серии — сырьём (линковку серии сделает раскладка).
6. **Держатель оригинала** («Место хранения оригинала») и **источник эл. копии** — раздельно.
7. **Связанное издание** (для библиотек): название/автор-ответственность/год/URL издания.
8. Территория/масштаб/техника/проекция — если явно на карточке.

## Что НЕ надо делать на прогоне (сделаем оффлайн — не блокируйтесь)
- раскладывать по 70 полям каталога, нормализовать место (`place_normalize`), типизировать A1–C8,
  выводить DC Type, линковать серии/территории, считать «Год источника» — это раскладка v1.6,
  применяется к `records_full.jsonl` после;
- писать в Notion (канон п.5 — только мост, это моя часть).

## Гейт «источник готов к заливке»
Прогон источника считать готовым, только если по выборке карточек:
- «Описание»-текст непустой у всех; у картографических — есть ссылка на скан (19 или 63);
- нативные шифры сняты (архив — Фонд/Опись/Дело);
- сырьё дат и серий присутствует.
Картографическая карточка с пустым текстом / без ссылки на скан = **неполный скрап → пере-сбор**,
не «готово».

## Персонально

### РГАДА (прогон ГОТОВ) — сессия-с-прогонами
Проверить `records_full.jsonl` РГАДА на пункты 1–5 выше (особенно: полный текст карточки и
ссылки на скан — у rgada.info в `<img data-largeim>` есть максимальное разрешение, см.
`ЗАДАНИЕ_OCR-модуль…`, раздел РГАДА). Если всё снято — **пере-прогон НЕ нужен**, раскладку v1.6 и
заливку делаю я оффлайн. Если текст/скан не снят (как у ГПИБ) — точечно дособрать ДО заливки.

### РГИА (прогон ИДЁТ) — сессия-с-прогонами
Пока идёт — убедиться, что снимаются пункты 1–5, прежде всего **полный текст карточки, ссылка на
скан, Фонд/Опись/Дело**. Доснять на живом прогоне дешевле, чем пере-прогон потом.
(Отдельно помнить про троттлинг иностранного IP — многозапросные обходы РФ-архивов с рос. IP.)

### Пермская краевая библиотека (АДАПТЕР ПИШЕТСЯ) — Codex
Писать адаптер СРАЗУ под этот принцип и под v1.6 (`ЗАДАНИЕ_адаптеры_новые-правила-полей_v1.6`):
полный текст карточки → «Описание»; ссылка на скан → 19/63; все шифры; даты/серия сырьём;
не повторить брак ГПИБ (пустое «Описание», нет ссылки на скан, склейка слов в названии без пробелов).
Применить общие модули: `place_normalize`, правила типизации (`sweep_candidate_type::RULES`),
алиасы серий (`fix_series_number::SERIES`).
